# Кухни мира: бриф с кодом на 180 минут

Для ручной реализации на React + Vite, Express и MySQL. Подготовлено 12 ноября 2026 года.

**Как пользоваться:** на репетиции проходи этапы последовательно; на конкурсе смотри на время и выполняй обязательный минимум. В каждом этапе есть файлы, код, проверка результата и условие остановки. Финальные версии всех файлов находятся в архиве.

**Честная оценка объёма:** эталон содержит порядка тысячи строк исходников и конфигурации, часть строк длинные. Это учебный материал для разбора и репетиции, а не обещание, что весь код получится впервые набрать за три часа. Если нет привычки быстро писать Express + SQL + React, ориентируйся на ядро и вычёркивай дополнения. Не расходуй последние 25 минут на новые функции.

В PDF прямо предусмотрено частичное выполнение. MySQL обязателен. Время включает настройку и сдачу. Расписание ниже — моя рекомендация, а не официальный регламент этапов.

## Маршрут и отсечки

| Время | Результат | При отставании |
|---|---|---|
| 0–15 | Доступы, зависимости, запуск Vite и Express | Сразу выясни способ запуска по выданному host |
| 15–30 | Схема MySQL и справочники | Не создавай покупки и избранное |
| 30–50 | Регистрация, вход, токен, защита страниц | Доведи вход до рабочего состояния |
| 50–75 | Каталог, детали, сортировки, фильтры, пагинация | Сначала список и сортировки, затем фильтры |
| 75–115 | Создание, редактирование, свои рецепты, изображения, удаление | Общая форма и сохранение важнее админских дополнений |
| 115–135 | Минимальная админка | Обязательно вход и список; справочники/восстановление — дополнение |
| 135–155 | Конструктор по ингредиентам | Делай только при рабочем ядре |
| 155–180 | Проверка, исправления, сборка и сдача | Новые функции больше не начинай |

По отдельным строкам критериев: регистрация и вход SPA — до 4,5; список с данными и сортировками — до 4; создание и редактирование с валидацией/подсветкой — до 6,5; свои рецепты — до 2,85; удаление/права/подтверждение — до 2,15; конструктор — до 5. Это максимумы при полном выполнении соответствующих строк. Баллы за API и админку проверяются отдельно. Числовой прогноз результата не даю: в PDF есть противоречия, а полноту засчитывает эксперт.

## Что покрывает эталон

Регистрация и вход user; токен в MySQL; защита API и страниц; список, четыре сортировки, фильтры и пагинация; просмотр рецепта; создание/редактирование одной формой; шаги и ингредиенты; загрузка и удаление изображений, выбор основного; миниатюры 350×200 WebP contain; свои рецепты; мягкое удаление с модальным подтверждением; админский вход, список, категории и ингредиенты, восстановление и окончательное удаление; конструктор по всем выбранным ингредиентам.

**Сознательно не реализованы:** водяные знаки и их обновление, покупки/оплата/webhook/прогресс, избранное, уведомления, создание и редактирование рецептов через отдельную HTML-форму админки. Создание и редактирование рецептов есть в пользовательском SPA. Админский API-токен не выдаётся. Админская сессия хранится в памяти процесса: после перезапуска войди снова. У одного пользователя один действующий API-токен; новый вход заменяет старый.

**Выданный HTML-шаблон отсутствует среди приложений.** В эталоне собственный простой CSS для репетиции; он не означает выполнение критерия использования выданного шаблона или Bootstrap. На конкурсе используй выданные стили и разметку, сохраняя React-логику из примеров. Порядок подключения описан в этапе 1.

## Быстрый запуск готового эталона для репетиции

Распакуй архив, открой терминал в папке `source`. Нужны Node.js, npm и уже работающий MySQL с отдельной пустой учебной базой. Здесь нет установки MySQL: на конкурсе его реквизиты должны выдать. Не запускай инициализацию в чужой рабочей базе.

```powershell
npm ci
npm --prefix client ci
Copy-Item .env.example .env
Copy-Item client/.env.example client/.env
```

Вручную заполни `.env`: DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME; выданные ADMIN_EMAIL и ADMIN_PASSWORD; собственную длинную SESSION_SECRET. Для учебного наполнения укажи DEMO_PASSWORD. В `client/.env` запиши VITE_CLIENT — выданный логин. Значения с `#`, пробелом или другими специальными символами заключай в двойные кавычки: иначе `.env` может прочитать `#` как комментарий. Не публикуй значения доступа в отчёте.

Пароль учебного пользователя выбирай по правилам регистрации. Команда db:init создаёт недостающие таблицы и администратора, если его email отсутствует; существующий аккаунт не перезаписывает. Это предполагает нашу схему. Если организаторы выдали готовую БД с другой схемой, сначала выясни правила её использования.

```powershell

npm run dev
```

Во втором терминале, тоже из `source`:

```powershell

```

Открой адрес, который выведет Vite. Учебный пользователь: `student@example.test`, пароль — твой DEMO_PASSWORD. Вход админа — `/admin`, данные из задания. `db:seed` создаёт шесть рецептов и цветные учебные изображения, а не фотографии блюд; повторное наполнение того же пользователя пропускается.

Для запуска собранного приложения останови сервер разработки Express, затем выполни `npm run build` и `npm start`. Открывай Express на порту из PORT; Vite для такого запуска не нужен.

## Этап 2. 15–30 минут: MySQL

**Цель:** семь связанных таблиц, хеш администратора, справочники. База уже создана организаторами или тобой в учебной среде. Код не создаёт саму базу и не требует CREATE DATABASE на конкурсе.

Категория удаляется с RESTRICT, даже если связанные рецепты мягко удалены. Удаление ингредиента каскадно убирает связи из recipe_ingredients. Позиция шага в БД называется position; в API поле возвращается как order. Изображение по умолчанию определяется в recipe_images, дублировать image_path в recipes не требуется для этого эталона.

**Файл: `server/schema.sql`.**

```sql
CREATE TABLE IF NOT EXISTS users (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  email VARCHAR(255) NOT NULL UNIQUE,
  password VARCHAR(255) NOT NULL,
  role ENUM('user','admin') NOT NULL DEFAULT 'user',
  token CHAR(64) NULL UNIQUE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS categories (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(40) NOT NULL UNIQUE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS ingredients (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  title VARCHAR(20) NOT NULL UNIQUE,
  unit VARCHAR(10) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS recipes (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  title VARCHAR(20) NOT NULL,
  description VARCHAR(250) NOT NULL,
  cooking_time INT UNSIGNED NOT NULL,
  difficulty VARCHAR(10) NOT NULL,
  price DECIMAL(10,2) NOT NULL DEFAULT 0,
  category_id INT UNSIGNED NOT NULL,
  user_id INT UNSIGNED NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted_at DATETIME NULL,
  FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE RESTRICT,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE RESTRICT
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS recipe_images (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  recipe_id INT UNSIGNED NOT NULL,
  path VARCHAR(255) NOT NULL,
  thumbnail VARCHAR(255) NOT NULL,
  is_default BOOLEAN NOT NULL DEFAULT FALSE,
  FOREIGN KEY (recipe_id) REFERENCES recipes(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS recipe_ingredients (
  recipe_id INT UNSIGNED NOT NULL,
  ingredient_id INT UNSIGNED NOT NULL,
  quantity DECIMAL(10,2) NOT NULL,
  unit VARCHAR(10) NOT NULL,
  PRIMARY KEY (recipe_id, ingredient_id),
  FOREIGN KEY (recipe_id) REFERENCES recipes(id) ON DELETE CASCADE,
  FOREIGN KEY (ingredient_id) REFERENCES ingredients(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

CREATE TABLE IF NOT EXISTS steps (
  id INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  recipe_id INT UNSIGNED NOT NULL,
  title VARCHAR(40) NOT NULL,
  description VARCHAR(255) NOT NULL,
  position INT UNSIGNED NOT NULL,
  FOREIGN KEY (recipe_id) REFERENCES recipes(id) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**Файл: `server/db.js`.**

```javascript
import mysql from 'mysql2/promise';

export const db = mysql.createPool({
  host: process.env.DB_HOST,
  port: Number(process.env.DB_PORT || 3306),
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  charset: 'utf8mb4',
  decimalNumbers: true,
  connectionLimit: 5
});

export async function query(sql, values = [], connection = db) {
  const [rows] = await connection.query(sql, values);
  return rows;
}

export function fail(status, message, errors) {
  const error = new Error(message);
  Object.assign(error, { status, errors });
  throw error;
}

export function invalid(errors) {
  if (Object.keys(errors).length) fail(422, 'Invalid fields', errors);
}
```

**Файл: `server/init.js`.**

```javascript
import { readFile } from 'node:fs/promises';
import bcrypt from 'bcryptjs';
import { db, query } from './db.js';

try {
  const sql = await readFile(new URL('./schema.sql', import.meta.url), 'utf8');
  for (const statement of sql.split(';').map(s => s.trim()).filter(Boolean)) await query(statement);
  const email = process.env.ADMIN_EMAIL;
  if (!email) throw new Error('Укажите ADMIN_EMAIL');
  const [existing] = await query('SELECT id FROM users WHERE email = ?', [email]);
  if (!existing) {
    if (!process.env.ADMIN_PASSWORD) throw new Error('Укажите выданный ADMIN_PASSWORD');
    await query('INSERT INTO users(name,email,password,role) VALUES(?,?,?,?)', ['Администратор', email, await bcrypt.hash(process.env.ADMIN_PASSWORD, 10), 'admin']);
  }
  console.log('Схема готова; существующий аккаунт администратора не изменён');
} finally {
  await db.end();
}
```

export async function listRecipes(params, user, admin = false) {
  const conditions = admin ? ['1=1'] : ['r.deleted_at IS NULL'];
  const values = [];
  const add = (condition, value) => { conditions.push(condition); values.push(value); };
  const numberParam = (key, minimum = 0) => {
    if (params[key] == null || params[key] === '') return null;
    const value = Number(params[key]);
    if (!Number.isFinite(value) || value < minimum) invalid({ [key]: ['Некорректное число'] });
    return value;
  };
  const page = numberParam('page', 1) ?? 1;
  const perPage = numberParam('per_page', 1) ?? 5;
  if (!Number.isInteger(page) || !Number.isInteger(perPage) || perPage > 50) invalid({ page: ['Некорректная пагинация'] });
  if (params.mine === '1') add('r.user_id = ?', user.id);
  if (params.category_id) add('r.category_id = ?', numberParam('category_id', 1));
  if (params.difficulty) add('r.difficulty = ?', params.difficulty);

  }

export async function saveRecipe(user, body, files, id) {
  const previous = id ? await getRecipe(id) : null;
  if (previous && previous.user_id !== user.id && user.role !== 'admin') fail(403, 'Forbidden for you');
  const ingredients = arrayField(body.ingredients || [], 'ingredients');
  const steps = arrayField(body.steps || [], 'steps');
  const removedIds = arrayField(body.remove_image_ids || [], 'images').map(Number);
  if (removedIds.some(imageId => !previous?.images.some(image => image.id === imageId))) invalid({ images: ['Изображение не принадлежит рецепту'] });
  const kept = previous?.images.filter(image => !removedIds.includes(image.id)) || [];
  const errors = recipeErrors({ ...body, ingredients, steps });
  if (kept.length + files.length < 2) errors.images = ['Необходимо минимум два изображения'];
  if (!(await query('SELECT id FROM categories WHERE id = ?', [Number(body.category_id) || 0])).length) errors.category_id = ['Категория не найдена'];
  const available = new Set((await query('SELECT id FROM ingredients')).map(item => item.id));
  ingredients.forEach((item, index) => { if (!available.has(Number(item?.id))) errors[`ingredients.${index}.id`] = ['Ингредиент не найден']; });
  const formats = [];
  for (const file of files) {
    try {
      const metadata = await sharp(file.buffer).metadata();
      if (!['jpeg', 'png', 'webp'].includes(metadata.format) || !/\.(jpe?g|png|webp)$/i.test(file.originalname) || metadata.width < 500 || metadata.height < 500) throw new Error();
      formats.push(metadata.format);
    } catch { errors.images = ['Нужны JPG/PNG/WebP минимум 500×500, до 2 МБ']; }
  }
  invalid(errors);
  const newImages = [];
  const connection = await db.getConnection();
  try {
    for (const [index, file] of files.entries()) {
      const filename = randomUUID();
      const image = { path: `/uploads/${filename}.${formats[index]}`, thumbnail: `/uploads/${filename}.webp` };
      if (formats[index] === 'webp') image.path = `/uploads/${filename}-original.webp`;
      newImages.push(image);
      await writeFile(path.join(uploadsDirectory, path.basename(image.path)), file.buffer);
      await sharp(file.buffer).rotate().resize(350, 200, { fit: 'contain', background: 'white' }).webp().toFile(path.join(uploadsDirectory, path.basename(image.thumbnail)));
    }
    await connection.beginTransaction();

      id = result.insertId;
    }
    if (removedIds.length) await query('DELETE FROM recipe_images WHERE recipe_id=? AND id IN (?)', [id, removedIds], connection);
    for (const image of newImages) {
      const result = await query('INSERT INTO recipe_images(recipe_id,path,thumbnail) VALUES(?,?,?)', [id, image.path, image.thumbnail], connection);
      image.id = result.insertId;
    }
    const allImages = [...kept, ...newImages];
    let defaultId = allImages[0].id;
    if (body.default_image?.startsWith('old:')) defaultId = kept.find(image => image.id === Number(body.default_image.slice(4)))?.id || defaultId;

    for (const [index, step] of steps.entries()) await query('INSERT INTO steps(recipe_id,title,description,position) VALUES(?,?,?,?)', [id, step.title.trim(), step.description.trim(), index + 1], connection);
    await connection.commit();
  } catch (error) {
    await connection.rollback();
    await removeFiles(newImages);
    throw error;
  } finally { connection.release(); }
  await removeFiles(previous?.images.filter(image => removedIds.includes(image.id)) || []);
  return getRecipe(id);
}

[...removed, image.id] : removed.filter(id => id !== image.id))} />Удалить</label>{!removed.includes(image.id) && <label><input className="form-check-input" type="radio" name="default_image" checked={defaultImage === `old:${image.id}`} onChange={() => setDefaultImage(`old:${image.id}`)} />Основное</label>}</div>)}

Это внутреннее соглашение этого клиента и сервера: не переименовывай его только в одном месте. Ингредиенты API возвращает с id, title, quantity, unit; шаги — с order.

**Изображения:** проверяется реальный формат через sharp, расширение, минимум 500×500 и размер через multer. Новых файлов максимум 10 за один запрос — ограничение учебной реализации, в задании такой максимум не указан. Можно убрать/изменить лимит files после согласования. Всего после редактирования должно остаться минимум два изображения. Оригиналы сохраняются отдельно; thumbnail — настоящий файл 350×200 WebP, contain с белыми полями. Водяного знака в этом маршруте нет.

**Сохранение:** рецепт, связи, шаги и записи изображений меняются в транзакции; при ошибке новые файлы убираются. Файлы удалённых изображений удаляются после успешного сохранения. Шаги при редактировании пересоздаются, поэтому их id могут измениться; для выбранного объёма без покупок и прогресса это допустимо. Один default-флаг устанавливается всем изображениям одним UPDATE.

Пустая цена и 0 сохраняются как бесплатный рецепт. Платная цена должна быть больше 100. В задании цена опциональная, а покупка бесплатного проверяется через price=0 — это выбранная совместимая трактовка. Цена ограничена вместимостью DECIMAL(10,2).

## Этап 7. 135–155 минут: конструктор

**Начинай только при рабочем ядре.** В критериях за drag-and-drop, поиск по всем выбранным ингредиентам и обновление при изменении набора предусмотрено суммарно до 5 баллов.

Поэтому не нужно скачивать весь каталог или фильтровать только текущую страницу. HTML Drag and Drop не требует библиотеки. Кнопка добавления нужна также для клавиатуры и устройств без перетаскивания.

Замени заглушку:

**Файл: `client/src/Constructor.jsx`.**

```jsx
import { useEffect, useState } from 'react';
import { api } from './api.js';
import { RecipeCard } from './Catalog.jsx';
import { Pagination } from './ui.jsx';

export default function Constructor() {
  const [ingredients, setIngredients] = useState([]);
  const [selected, setSelected] = useState([]);
  const [page, setPage] = useState(1);
  const [result, setResult] = useState(null);
  const [problem, setProblem] = useState('');
  useEffect(() => { api('/ingredients').then(setIngredients).catch(error => setProblem(error.message)); }, []);
  const search = new URLSearchParams({ page: String(page) });
  selected.forEach(id => search.append('ingredients[]', id));
  const query = search.toString();
  useEffect(() => {
    let active = true;
    setResult(null); setProblem('');
    api('/recipes?' + query).then(data => { if (active) setResult(data); }).catch(error => { if (active) setProblem(error.message); });
    return () => { active = false; };
  }, [query]);
  function add(id) {
    id = Number(id);
    if (!ingredients.some(item => item.id === id)) return;
    setSelected(previous => previous.includes(id) ? previous : [...previous, id]); setPage(1);
  }
  function remove(id) { setSelected(previous => previous.filter(value => value !== id)); setPage(1); }
  return <><h1>Найти по ингредиентам</h1><p>Перетащите ингредиенты в область или нажмите на них. Рецепт должен содержать все выбранные ингредиенты.</p>
    <div className="row">{ingredients.map(item => <button key={item.id} draggable onDragStart={event => event.dataTransfer.setData('text/plain', item.id)} onClick={() => add(item.id)}>{item.title}</button>)}</div>
    <section className="dropzone panel" aria-label="Выбранные ингредиенты" onDragOver={event => event.preventDefault()} onDrop={event => { event.preventDefault(); add(event.dataTransfer.getData('text/plain')); }}>
      {!selected.length && <p>Перетащите сюда ингредиенты</p>}{selected.map(id => <button key={id} onClick={() => remove(id)}>{ingredients.find(item => item.id === id)?.title} ×</button>)}
    </section>
    {problem && <p className="error">{problem}</p>}{!result && !problem && <p>Загрузка…</p>}
    {result && <><p>Найдено: {result.total}</p><div className="grid">{result.data.map(recipe => <RecipeCard key={recipe.id} recipe={recipe} />)}</div><Pagination result={result} onPage={setPage} /></>}
  </>;
}
```

**Проверка:** перетащи два ингредиента; результат содержит оба. Добавь третий — список обновился; убери его — результат восстановился. Дубликаты не добавляются. Карточка открывает рецепт. Фильтр работает по всей базе, пагинация — после фильтра. Пустой набор показывает все активные рецепты. Дополнительные ингредиенты в рецепте допустимы.

**Отсечка 155 минут:** останови разработку новых функций. Даже если «осталось совсем чуть-чуть», дальше только проверка и сдача.

Не запускай npm start поверх уже работающего npm run dev на том же порту. Сначала останови предыдущий процесс в его терминале. Для разработки нужны Vite и Express; после сборки достаточно Express, который отдаёт client/dist, API, uploads и админку с одного адреса.

- В консоли браузера нет необработанных ошибок, в запросах API есть Client, на защищённых — Bearer.

**175–180:** проверь папку source, минимум два осмысленных коммита, правильный серверный Git и фактическое открытие host. ## Если что-то сломалось

| Симптом | Проверка / исправление |
|---|---|
| Unexpected token '<' при чтении JSON | Запрос попал в SPA. Проверь /api, proxy и порядок маршрутов |
| В dev есть CSS, после сборки нет | /base.css раздаёт Express из public; проверь передачу этой папки |
| Ошибка EADDRINUSE | На том же порту остался второй процесс; останови свой предыдущий процесс |
| Ошибка multer / нет файлов | FormData, имя images[], Content-Type вручную не задавать |
| Одно фото заменили — сохранение отклонено | После удаления и добавления суммарно должно остаться минимум два |
| Токен теряется после F5 | Проверь localStorage и загрузку /api/me; там должен храниться только token |
| После второго входа первый браузер получает 401 | В эталоне один токен на user. Для двух пользователей создай два аккаунта |
| При вставке пароль с # перестал работать | Заключи значение .env в кавычки. Уже созданный аккаунт автоматически не перезаписывается |
| Рецепт виден после удаления | Убедись, что SELECT содержит deleted_at IS NULL и список перезагрузился |
| Мои рецепты теряются на странице 2 | user_id должен фильтроваться в SQL до LIMIT/OFFSET |
| Конструктор находит рецепт только с одним из двух ингредиентов | Нужны DISTINCT и HAVING COUNT = число выбранных, а не только WHERE IN |
| Express ругается на '*' | Для Express 5 используй /{*splat}; этот маршрут стоит после API |
| Sharp не установился | Проверь совместимость Node, сеть и доступность готовых пакетов; не меняй библиотеку посреди конкурса без необходимости. Если не удаётся — откажись от миниатюр осознанно и учитывай потерянные критерии |
